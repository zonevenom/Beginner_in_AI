二、每个模块的内部结构（三件套）

你对我的要求是「每个小安排 = 理论 + 练习 + 项目」，所以每个模块内部都是同一个形状：

flowchart LR T["① 理论讲稿
大白话 + 比喻
+ 资料出处"] --> Q["② 练习题 5~8 道
概念/代码/动手
+ 详细解析"] Q --> P["③ 项目计划书
工具环境/结构/流程图
/逐步操作/进化方向"] P --> R["④ 复盘
错题本 + 一句话总结"]

为什么必须是这个顺序？

  • 只听理论 → 以为自己会了，一动手全懵（"知识的错觉"）
  • 只做项目 → 换个需求就不会了，因为你不知道为什么这么写
  • 练习是理论到项目之间的缓冲垫，故意设计得比理论难一点点、比项目简单一点点

四、三条学习主线（同一批知识，三种切法）

  1. 按"数据流"切：用户输入 → 提示词拼装 → 模型生成 → 后处理 → 返回用户。 RAG 就是在这个链条中间插了"检索"，Agent 就是插了"调工具"。
  2. 按"出错方式"切：模型不知道 → 要 RAG；模型不会算/不能操作 → 要工具；模型不听话 → 要提示工程；模型太贵太慢 → 要工程优化。
  3. 按"交付物"切：脚本 → 界面 → 服务 → 产品。每升一级，多一层工程能力。

建议你每学完一个模块，回到这张图上用手指一下："我现在站在哪一格？"——这是防止迷路最有效的办法。
