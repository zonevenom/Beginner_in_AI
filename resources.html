一份资料的"该停"信号

看到以下情况，立刻关掉资料回讲稿：

  • 开始出现你看不懂的数学符号，且不是"概念级"的（如矩阵乘法可以，偏导推导不行）
  • 开始讲训练、显存、分布式（这不是你的方向）
  • 同一个概念讲了 3 页还没进入"怎么用"
  • 你已经读了 20 分钟，但说不出刚才读了什么

资料是给你用的，不是给你供着的。

how to read

三类资料怎么分工

PDF 强在体系、网页强在最新、仓库强在真实工程。用错场景，就是自找劝退。

二、三类资料怎么分工（这是重点）

类型强项弱项我的用法
PDF 电子书体系完整、概念严谨、有推导厚、枯燥、容易劝退只把"讲稿里没讲透的概念"回查原文
网页文档最新、可运行示例、有中文碎片化、版本变化快写代码时当"说明书"，遇到 API 不会就查
GitHub 仓库真实工程结构、可跑没有教学顺序、代码质量参差项目卡住时看别人怎么组织文件、怎么处理异常

三、关于"英文资料"的说明

你担心看英文吃力。我的处理方式是：

  1. 优先选中文原生资料——下面 3 本 PDF、6 个网页里，绝大多数本身就是中文写的，不存在"翻译腔"问题。
  2. 少数英文页面（如 OpenAI Cookbook、LangChain 文档）我不会让你直接读，我会把里面关键内容用中文重写进讲稿，只把链接作为出处标注。
  3. 术语保留英文原词（如 embedding、prompt、token）。原因：中文译名不统一，你以后搜资料、看报错、面试都用英文词。我会在第一次出现时给中文解释。

五、使用纪律（三条）

  1. 不要收藏了就当学了。 资料区的文件只在两种情况下打开：① 讲稿里某个概念你没懂 ② 你想确认某句话的原始出处。
  2. 不要同时开三份资料。 一个概念只查一处，查完就回讲稿。多源对照是研究者干的事，不是初学者干的事。
  3. GitHub 仓库不要 clone 一堆。 每个模块最多看 1 个仓库的 README，项目阶段才看代码。
