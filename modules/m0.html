【这一讲要解决什么】

学完这一讲，你能：

  1. 用人话解释"大模型是什么"（不用一个术语）
  2. 在自己的电脑上跑通第一次 API 调用，看到模型回你话
  3. 看懂返回结果里的每一个字段
  4. 遇到 5 种最常见的报错，知道去哪查

注意：这一讲不需要任何数学。 一个公式都没有。谁跟你说学 AI 必须先学微积分，那是在吓唬你——至少在"应用开发"这条路上不是。

一、大模型到底是个什么东西

先说结论

它是一个极其擅长"接话"的机器。 你给它一段文字，它算出"下一个字最可能是什么"，然后把这个字接上去，再算下一个，一直接下去。

就这么简单。ChatGPT、DeepSeek、通义、文心，本质上都在做同一件事：接话。

一个你每天在做的事

你朋友说："今天下班路上堵得……"

你脑子里会自动蹦出："要死"、"不行"、"一塌糊涂"。

你没有"思考"，你只是根据经验，觉得这几个词最可能接在后面。

大模型干的是同一件事，只是它"读过"的书比你多几百万倍，所以它接得更准、更像个懂行的人。

那它为什么显得"懂很多"？

因为它读过的东西太多了。它把互联网上大量的文字"压缩"进了一堆数字里（这些数字叫参数）。

你可以把它想象成一个看了几千万本书、但从不做笔记的人：

  • 他能跟你聊哲学、聊代码、聊菜谱——因为都看过
  • 但他记不清具体页码——所以他会"编"，编得还挺像
  • 他看完就忘，不会记住你上次跟他说的话（除非你把话再贴给他一遍）

这三条，解释了后面 90% 的"AI 怎么这么蠢"的现象。

由此推出三个必须记住的结论

现象原因对策（后面会学）
它一本正经地胡说（幻觉）它在"接得像"而不是"查得准"RAG：把真材料塞给它看（M4）
它记不住上一轮对话它天生没有记忆把历史对话每次重新发一遍（M2）
它算数经常错它是"接话"不是"计算"让它调工具算（M6）

把这张表记住。你后面 7 个模块，全是在解决这三行问题。

二、三个必须懂的词

1. Token（词元）—— 它按"块"收费

大模型不是按"字"处理文字的，它先把文字切成一块一块，每一块叫一个 token。

  • 英文里，一个 token 大约 = 0.75 个单词
  • 中文里，一个汉字通常是 1~2 个 token（常用字 1 个，生僻词可能 2 个）

为什么要在意？ 因为：

  1. 它按 token 收费（输入多少 token、输出多少 token，分别计价）
  2. 它一次只能看固定数量的 token（见下一条）

比喻：坐出租车。不是你坐多远算多远，而是按"跳表次数"算钱。token 就是跳表次数。

2. 上下文窗口（Context Window）—— 它的"短期记忆"

模型一次能"看到"的 token 总量是有上限的，这个上限叫上下文窗口。

  • 现在主流模型大概是 几万到几十万 token（各模型不同，以官网为准）
  • 超过上限，最早的内容会被挤出去

比喻：一张书桌。桌上能摊开的纸就这么多，新纸放上来，旧纸就得掉下去。 它不是"忘了"，是"被挤下桌了"。

这解释了：

  • 为什么长对话聊到后面，它开始"忘记"你前面说的设定
  • 为什么 RAG 不能把整本书塞进去，必须先检索、再挑几段
  • 为什么"把 100 页 PDF 直接扔给模型"通常效果很差

3. Temperature（温度）—— 想象力的旋钮

一个 0 到 2 之间的数字（常用 0~1）：

值效果什么时候用
0 ~ 0.3最稳、最一致，同样的问题基本同样答案查资料、写代码、提取信息、输出 JSON
0.7 左右有点变化，但不离谱日常聊天
1.0 以上很飘，可能很有创意，也可能胡说写文案、起名字、头脑风暴

比喻：收音机的"清晰度"旋钮。调低，信号干净但死板；调高，有杂音但偶尔能收到意外的台。

这是你最早能"控制"模型的一个参数。 记住：要准确性就调低，要创意就调高。

三、API 是什么：一次"点菜"的全过程

为什么不用网页版，要用 API？

网页版（chat.deepseek.com）是给人用的；API 是给程序用的。

你想让程序自动干活——批量处理 1000 条评论、接进你自己的网页、每天定时总结新闻——就必须走 API。

点菜比喻

点菜API
你走进餐厅你向 https://api.deepseek.com 发请求
你说"一份宫保鸡丁，不要辣"你发一段 JSON：{"model":"deepseek-chat", "messages":[...]}
服务员记下菜单服务器收到请求
厨房做菜模型生成文字
端上来一盘菜服务器返回 JSON，里面有文字
你付钱按 token 计费

整个过程是"一问一答"：你发一个请求，它回一个结果，连接就断了。它不会主动找你。

请求长什么样（不用背，看懂结构就行）

三个 role 是核心：

role谁说的作用
system你（在后台偷偷说）定人设、定规矩。用户看不见
user用户提问
assistant模型回答（多轮对话时，历史回答也要放回去）

system 是你最有力的武器。 同一个问题，加一句 system，风格能完全变。M1 会专门练这个。

【常见误解】

误解 1："它在思考。" 不。它在算概率。它没有意图、没有情绪、不知道自己在说什么。"它理解我"是一种错觉，虽然这个错觉很有用。

误解 2："我数学不好，学不了 AI。" 做应用开发，你需要的是"知道 embedding 是什么感觉""知道温度调低会更稳"，不需要会推导。真正的数学在"训练模型"那一层，那不是你的方向。

误解 3："模型越贵越好。" 错。做 RAG 时，检索质量比模型大小重要得多。一个便宜的模型 + 好的检索，能打败贵模型 + 烂检索。这是 M4/M5 的核心思想。

误解 4："我要先把 Python 学完再开始。" 不要。"学完 Python"永远不存在。你现在的水平（变量、循环、函数）足够开始，缺什么补什么，缺的部分我会在项目里标注。

🧠 第 2 题（概念）· 判断并改错

判断下面 5 句话对错，错的请改正：

  1. 中文里一个汉字一定等于一个 token。
  2. 上下文窗口满了以后，模型会自动把旧内容存到硬盘上，下次接着用。

第 1 题 · 幻觉的根源

参考答案

说法错在：它把大模型当成了"检索系统"，但大模型是"生成系统"——它不查，它接。

  • 搜索引擎：有一份确定的文档库。你问它，它去匹配，找到原文，把原文给你。找不到就说"没有"。
  • 大模型：它把训练时读过的文字"压缩"成了数字（参数），生成时是算下一个 token 的概率，然后接上去。它没有原文可查。

所以当它被问到"没读过的事实"时，它不会说"我不知道"——因为它的任务是"接下去"，而"接下去"最自然的接法就是编一个看起来对的东西。这在学术上叫幻觉（hallucination）。

思路拆解

  1. 先定性：这是"检索 vs 生成"的混淆。
  2. 再解释机制：它按概率接话，不是按索引查询。
  3. 最后说后果：不知道也不会承认，因为"承认不知道"不是它训练时最常见的接法。

常见错误

  • ❌ 只答"因为它数据不够"。数据再多也会编，这不是数据量问题，是机制问题。
  • ❌ 答"因为它没有联网"。联网也治不了幻觉，它会把搜到的内容理解错再编。
  • ✅ 高分答案会补一句：所以后来有了 RAG——把真材料放进上下文里，让它"读"而不是"回忆"。

这一题的答案，就是你 M4 整个模块存在的理由。

第 2 题 · 判断并改错

#判断正确答案与解释
1❌ 错汉字通常 1~2 个 token，生僻字、英文混排、标点都会影响。没有任何"一定 1:1"的规则。考试里凡是出现"一定""必然"，基本都错
2❌ 错不会存硬盘。模型是"无状态"的，窗口满了就截断/丢弃最早的 token，没有"下次接着用"。要它记住，必须每次把历史重新发过去（M2 的核心）
3⚠️ 半对半错temperature=0 时结果高度可复现，但不是 100% 相同。原因：服务端批处理、浮点误差、模型小版本更新都会让结果有微小差异。正确说法："趋近于确定"，不是"完全一样"
4✅ 对system 是后台悄悄说的话，用户界面看不到，但它会强烈影响语气、格式、边界。这是你控制模型最有效的手段
5❌ 错输入输出都计费，而且输出通常更贵（2~4 倍）。所以"把 10 万字文档全塞进去"不只是慢，还非常贵

思路拆解

这题考的不是记忆，是"绝对化表述"的敏感度。AI 领域几乎没有"一定"，因为一切都是概率和近似。

常见错误

  • 第 3 题最容易答错。很多人以为"温度=0 就是确定性的"。记住：工程上没有绝对确定，只有"足够稳定"。

第 3 题 · 算一笔账

参考答案

第 1 问：每天多少钱？

第 2 问：压 system 能省多少？

第 3 问：一个月多少钱？

思路拆解

三步走：先算总量（token）→ 再乘单价 → 最后看占比。

关键在第 2 问的"占比"：2 元 / 44 元 ≈ 4.5%。 一个月省 60 块。值得做，但不是最值得做的事。

更重要的结论（这题真正的考点）

看这个比例：输出花了 32 元，占 73%。

所以成本优化的第一优先级是"少让它说话"，不是"少给它材料"。 具体做法：让它"只输出 JSON""回答不超过 50 字""不要解释过程"。 这一条，比压 system 有效 10 倍。

常见错误

  • ❌ 忘记单位换算（1200 token 是 0.0012 百万，不是 1200 百万）
  • ❌ 把输入输出单价混用
  • ✅ 高分答案会指出"输出占比高，所以优化输出优先"

1. 项目要做什么

一句话

做一个能在命令行里跟你连续对话的小工具：输入问题，它回答；输入 exit 退出；退出时告诉你这次花了多少 token。

验收标准（做到这 6 条才算完成）

  • 双击运行（或命令行 python main.py）能启动
  • 启动后先显示一句欢迎语，提示可以输入 exit 退出
  • 能连续问 3 个以上问题，不会崩
  • 每个回答前面有 你： 和 AI：，能分清谁在说话
  • 输入 exit（大小写都行）能正常退出
  • 退出时打印本次对话的总 token 数

明确不做什么（防止跑偏）

  • ❌ 不做记忆（M2 才做）
  • ❌ 不做界面（M2 才做）
  • ❌ 不接数据库
  • ❌ 不调用第三方库（除了 openai 和 dotenv）

这一版丑、笨、没记忆，但它跑得起来。跑得起来比什么都重要。

4. 项目流程图

flowchart TD A([开始]) --> B[打印欢迎语
读取 .env 里的 Key] B --> C{Key 存在吗} C -- 否 --> C1[提示"没找到 Key"
并退出] C -- 是 --> D[初始化 client
指向 DeepSeek] D --> E[/等待用户输入
input/] E --> F{输入是 exit?} F -- 是 --> Z[打印总 token 数
结束] F -- 否 --> G[组装 messages
system + 本轮 user] G --> H[调用 API
chat.completions.create] H --> I{调用成功?} I -- 否 --> I1[打印报错摘要
继续下一轮] I1 --> E I -- 是 --> J[取出 content 打印] J --> K[累加 prompt/completion token] K --> L[追加写入 chat_log.txt] L --> E

看懂这张图的三个要点

  1. 循环体是"等待输入 → 调用 → 打印 → 回去等"，exit 是唯一的出口。
  2. 报错不能让程序崩，要能回到等待输入（这叫"容错"）。
  3. token 累加在循环里，不在循环外。
