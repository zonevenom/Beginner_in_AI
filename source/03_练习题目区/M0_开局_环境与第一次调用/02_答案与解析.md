## 第 1 题 · 幻觉的根源

### 参考答案

**说法错在**：它把大模型当成了"检索系统"，但大模型是"生成系统"——它不查，它**接**。

- **搜索引擎**：有一份确定的文档库。你问它，它去**匹配**，找到原文，把**原文**给你。找不到就说"没有"。
- **大模型**：它把训练时读过的文字"压缩"成了数字（参数），生成时是**算下一个 token 的概率**，然后接上去。它**没有原文可查**。

所以当它被问到"没读过的事实"时，它不会说"我不知道"——因为它的任务是"接下去"，而"接下去"最自然的接法就是**编一个看起来对的东西**。这在学术上叫**幻觉（hallucination）**。

### 思路拆解

1. 先定性：这是"检索 vs 生成"的混淆。
2. 再解释机制：它按概率接话，不是按索引查询。
3. 最后说后果：不知道也不会承认，因为"承认不知道"不是它训练时最常见的接法。

### 常见错误

- ❌ 只答"因为它数据不够"。**数据再多也会编**，这不是数据量问题，是机制问题。
- ❌ 答"因为它没有联网"。**联网也治不了幻觉**，它会把搜到的内容理解错再编。
- ✅ 高分答案会补一句：**所以后来有了 RAG——把真材料放进上下文里，让它"读"而不是"回忆"。**

> 这一题的答案，就是你 M4 整个模块存在的理由。

## 第 2 题 · 判断并改错

| # | 判断 | 正确答案与解释 |
|---|---|---|
| 1 | ❌ 错 | 汉字**通常** 1~2 个 token，生僻字、英文混排、标点都会影响。**没有任何"一定 1:1"的规则。**考试里凡是出现"一定""必然"，基本都错 |
| 2 | ❌ 错 | **不会存硬盘。**模型是"无状态"的，窗口满了就**截断/丢弃**最早的 token，没有"下次接着用"。要它记住，必须每次把历史重新发过去（M2 的核心） |
| 3 | ⚠️ 半对半错 | temperature=0 时结果**高度可复现**，但不是 100% 相同。原因：服务端批处理、浮点误差、模型小版本更新都会让结果有微小差异。**正确说法："趋近于确定"，不是"完全一样"** |
| 4 | ✅ 对 | `system` 是后台悄悄说的话，用户界面看不到，但它会强烈影响语气、格式、边界。**这是你控制模型最有效的手段** |
| 5 | ❌ 错 | **输入输出都计费**，而且**输出通常更贵**（2~4 倍）。所以"把 10 万字文档全塞进去"不只是慢，还非常贵 |

### 思路拆解

这题考的不是记忆，是**"绝对化表述"的敏感度**。AI 领域几乎没有"一定"，因为一切都是概率和近似。

### 常见错误

- 第 3 题最容易答错。很多人以为"温度=0 就是确定性的"。**记住：工程上没有绝对确定，只有"足够稳定"**。

## 第 3 题 · 算一笔账

### 参考答案

**第 1 问：每天多少钱？**

```
输入：5000 次 × 1200 token = 6,000,000 token = 6 百万
      6 × 2 元 = 12 元

输出：5000 次 × 800 token = 4,000,000 token = 4 百万
      4 × 8 元 = 32 元

合计：12 + 32 = 44 元 / 天
```

**第 2 问：压 system 能省多少？**

```
每次省 300 - 100 = 200 token
每天省 5000 × 200 = 1,000,000 token = 1 百万
1 × 2 元 = 2 元 / 天
```

**第 3 问：一个月多少钱？**

```
44 × 30 = 1320 元 / 月
```

### 思路拆解

三步走：**先算总量（token）→ 再乘单价 → 最后看占比**。

关键在第 2 问的"占比"：2 元 / 44 元 ≈ **4.5%**。
一个月省 60 块。**值得做，但不是最值得做的事。**

### 更重要的结论（这题真正的考点）

看这个比例：**输出花了 32 元，占 73%。**

> 所以成本优化的**第一优先级是"少让它说话"**，不是"少给它材料"。
> 具体做法：让它"只输出 JSON""回答不超过 50 字""不要解释过程"。
> 这一条，比压 system 有效 10 倍。

### 常见错误

- ❌ 忘记单位换算（1200 token 是 0.0012 百万，不是 1200 百万）
- ❌ 把输入输出单价混用
- ✅ 高分答案会指出"输出占比高，所以优化输出优先"

## 第 4 题 · 找出 4 个问题

### 参考答案

| # | 问题 | 危害 |
|---|---|---|
| 1 | **API Key 硬编码在代码里** | 一旦上传 GitHub / 发给别人，Key 立刻泄露，被人盗刷。**最严重的问题** |
| 2 | **没有指定 `base_url`** | 会默认连 `api.openai.com`。你用的是 DeepSeek 的 Key，在 OpenAI 那边无效 → 直接 401 |
| 3 | **`temperature=1.5`** | 太高了。日常问答、要准确性的场景应该 0~0.3。1.5 会飘到语无伦次 |
| 4 | **`resp.choices[0].text`** | 属性不存在，会 `AttributeError`。正确是 `resp.choices[0].message.content` |

### 正确写法

```python
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
)

resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "你好"}],
    temperature=0.3,
)

print(resp.choices[0].message.content)
```

### 思路拆解

检查顺序：**安全（Key）→ 连接（base_url）→ 参数（temperature）→ 结果解析（字段名）**。
这个顺序就是"从大到小"，先解决会让程序完全跑不起来的，再解决让结果不好的。

### 常见错误

- 只找到 2~3 个。**第 2 个（base_url）最隐蔽**，因为代码不报错，只是连错了地方。
- 把 `temperature=1.5` 当成"错误"而不是"不合适"。它不报错，只是效果差——**这类问题最难发现**。

## 第 5 题 · 五个报错

| # | 报错 | 原因 | 第一步 |
|---|---|---|---|
| 1 | 401 AuthenticationError | Key 错 / 没读到 `.env` / Key 被删 | 打印 `os.getenv("DEEPSEEK_API_KEY")` 看是不是 `None`；检查 `.env` 文件名（别叫 `.env.txt`） |
| 2 | 402 Insufficient Balance | 余额不足 | 去平台充值，或换用有赠送额度的模型 |
| 3 | 429 RateLimitError | 请求太快/太多 | 加 `time.sleep(1)`，降低并发，或检查是不是循环里忘了暂停 |
| 4 | ModuleNotFoundError | 没装库，**或虚拟环境没激活** | 先看命令行有没有 `(.venv)`；有就 `pip install openai`，没有就先 activate |
| 5 | 'python' 不是内部或外部命令 | Python 没装好 / 安装时没勾 "Add to PATH" | 重装 Python，**勾选 Add Python to PATH**；或用 `py` 命令代替 `python` |

### 思路拆解

报错的**前三位数字**就是答案：

- **4xx = 你的错**（Key、钱、频率、参数）
- **5xx = 服务器的错**（等一会儿重试）
- **不是 openai 开头的错** = 环境问题（没装、没激活、PATH 没配）

### 常见错误

- 第 4 题：直接 `pip install`，但其实是 venv 没激活。**装了也白装**，因为装到全局去了。
- 第 1 题：以为 Key 错了，其实是 `.env` 文件被记事本存成了 `.env.txt`（Windows 默认隐藏扩展名，这是经典坑）。

## 第 6 题 · 改造 hello_llm.py

### 参考实现

```python
import os
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

client = OpenAI(
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
)

total_prompt = 0
total_completion = 0

for i in range(3):
    q = input(f"[{i + 1}/3] 你想说点什么？（输入 exit 退出）：")

    if q.strip().lower() == "exit":
        print("拜拜，下次见。")
        break

    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是一个毒舌评论员，每次只回答一句话，带点讽刺但不做人身攻击。"},
            {"role": "user", "content": q},
        ],
        temperature=0.9,
    )

    print("AI：", resp.choices[0].message.content)
    print(f"  本次 token：输入 {resp.usage.prompt_tokens} / 输出 {resp.usage.completion_tokens}")

    total_prompt += resp.usage.prompt_tokens
    total_completion += resp.usage.completion_tokens

print(f"\n合计：输入 {total_prompt}，输出 {total_completion}，总计 {total_prompt + total_completion}")
```

### 逐块解释（这才是重点）

| 代码 | 为什么这么写 |
|---|---|
| `for i in range(3)` | 固定 3 次。用 `while True` 也行，但要自己管退出，容易写出死循环 |
| `q.strip().lower() == "exit"` | `strip()` 去掉首尾空格（用户常手滑打空格），`lower()` 让 `EXIT`/`Exit` 都能识别 |
| `break` | 跳出循环。**注意：`break` 后仍会执行循环外的 print 合计** |
| `system` 里写"只回答一句话" | 这是**输出长度控制**，直接降成本（见第 3 题结论） |
| `temperature=0.9` | 毒舌人设需要一点"飘"，太死板就不毒了 |
| `resp.usage.prompt_tokens` | 每次请求的用量。**注意是每次**，不是累计——所以要在循环里累加 |
| `total_prompt += ...` | 累加。缩进必须在循环内，否则只加最后一次 |

### 加分项 6：温度对比

**参考观察**：temperature=0.3 时，三次回答结构相似、用词接近；0.9 时，每次的比喻和语气都不同，偶尔会出现很妙的句子，也偶尔会跑偏。

> 一句话记录：**"低温度像同一个人的三次回答，高温度像三个不同的人在回答。"**

### 加分项 7：删掉 key 的报错

会看到类似：

```
openai.AuthenticationError: Error code: 401 - {'error': {'message': 'Authentication Fails...'}}
```

**注意它发生在"发请求"那一刻，不是"创建 client"那一刻。** 因为 `OpenAI(...)` 只是打包参数，真正联网是在 `.create()` 时。这个细节很多教程讲错。

### 常见错误

- ❌ 把 `total_prompt += ...` 写在循环外 → 只统计最后一次
- ❌ 用 `input()` 但在 IDE 的"运行"面板里跑 → 有的 IDE 不支持交互输入，会卡住。**用命令行跑**
- ❌ 忘了 `break` 后合计还是打印了，以为出 bug
- ⚠️ "毒舌"人设偶尔会被安全策略拦，返回空内容。**这不是你的 bug**，换个温和点的人设试试
