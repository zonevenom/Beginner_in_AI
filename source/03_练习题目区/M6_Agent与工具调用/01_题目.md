## 🧠 第 1 题（概念）· 该不该用 Agent

判断下面 6 个场景**该不该用 Agent**，并说明理由：

1. 一个"根据用户问题，检索文档然后回答"的问答机器人
2. 一个"帮我查明天北京天气，如果下雨就提醒我带伞，并把提醒加到我的日历"的助手
3. 一个"给 5000 条评论打情感标签"的批处理脚本
4. 一个"帮我分析这份 Excel，算出各区域销售额，并画图"的工具
5. 一个"自动回复客户邮件"的系统
6. 一个"我描述需求，它帮我改代码并跑测试"的编程助手

**附加问**：第 1 题如果"不该用 Agent"，那为什么市面上很多 RAG 产品都自称 Agent？

## 🛠️ 第 6 题（动手）· 三个工具的最小 Agent

**任务：**

实现一个带 3 个工具的 Agent：

| 工具 | 作用 |
|---|---|
| `calculate(expression)` | 算数学表达式（**不许用 `eval`**） |
| `get_current_time()` | 返回当前日期时间 |
| `search_notes(keyword)` | 在你自己的 20 条笔记里搜（关键词匹配即可） |

**要求：**

1. 用原生 Function Calling，不用框架
2. 有 `max_steps=6`
3. **每次工具调用都打印日志**：第几步、调了什么、参数是什么、返回什么
4. 测这 5 个任务：

| # | 任务 | 该调哪些工具 |
|---|---|---|
| 1 | "现在几点" | time |
| 2 | "1234 × 5678 等于多少" | calculate |
| 3 | "我的笔记里有没有提到退款的" | search_notes |
| 4 | "现在几点？顺便算一下 365×24" | time + calculate |
| 5 | "帮我订一张去上海的机票" | **没有工具，应该承认做不到** |

5. 记录第 4、5 题的**完整调用链**（几步、什么顺序）

**加分**：故意让 `calculate` 收到一个非法表达式（如 `1/0` 或 `abc`），看模型会不会自己修正。
