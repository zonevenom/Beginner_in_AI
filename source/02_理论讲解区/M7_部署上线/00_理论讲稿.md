## 【这一讲要解决什么】

学完这一讲，你能：

1. 判断你的应用该"部署到哪"（三种方案，各有适用场景）
2. 正确管理密钥（**这一条做错，后果最严重**）
3. 用 FastAPI 把功能包成一个接口，知道什么时候需要它
4. 加限流，防止被别人刷爆你的账户
5. 把三个项目包装成一份**能投的**作品集

## 一、先搞清楚"上线"有三个层次

| 层次 | 长什么样 | 谁能用 | 技术难度 |
|---|---|---|---|
| **L1 本地脚本** | `streamlit run app.py` | 只有你 | ⭐ |
| **L2 内网/临时链接** | 局域网 IP / 临时隧道 | 你和同事 | ⭐⭐ |
| **L3 公网服务** | `https://xxx.com` | 任何人 | ⭐⭐⭐ |

**大多数人卡在 L1 到 L2 之间，不是因为技术难，是因为"没做过，不知道从哪下手"。**

这一讲就是把这条路走通。

## 二、三种部署方案，怎么选

### 方案 A：Streamlit Community Cloud（最快，免费）

| 项 | 说明 |
|---|---|
| 怎么做 | 代码推到 GitHub → 在 share.streamlit.io 点几下 → 拿到链接 |
| 成本 | 免费 |
| 限制 | 需要 GitHub；国内访问速度一般；资源小（内存 1G 左右） |
| 适合 | **你的 P3/P5/P6/P7** |

**这是你该先走的路。** 从"没部署过"到"有链接"，最快 20 分钟。

### 方案 B：Hugging Face Spaces（免费，AI 圈常用）

| 项 | 说明 |
|---|---|
| 怎么做 | 建 Space → 选 Streamlit/Gradio → 上传文件 |
| 成本 | 免费（CPU 基础版） |
| 限制 | 需要 HF 账号；国内访问需要条件 |
| 适合 | 想让**海外同行/招聘方**看到 |

### 方案 C：国内云服务器（要花钱，但最"真"）

| 项 | 说明 |
|---|---|
| 怎么做 | 买一台轻量应用服务器（2 核 2G 起）→ 装 Python → 跑服务 → 配域名 |
| 成本 | 新用户首年通常有优惠，之后每月几十元 |
| 限制 | 要会一点 Linux；要备案（用域名的话） |
| 适合 | 想写"独立部署"进简历；或要给国内用户稳定访问 |

> 🛑 **买服务器之前先问我。** 我会告诉你买什么配置、有没有必要买、怎么避免"买了一台不会用"。

### 方案 D：内网穿透（临时演示用）

一行命令把本地端口暴露成公网地址（如 `cloudflared tunnel`、`ngrok`）。

**优点**：立刻能用，零配置。
**缺点**：**电脑一关就断**，且地址每次变。

> 只适合"临时发给朋友看 5 分钟"，**不适合写进简历**。

### 选择建议

```
想快速有链接 → A
想给海外看   → B
想写"独立部署" → C
临时演示     → D
```

## 三、密钥管理：这一节做错，会真出事

### 三种错误做法（每一种都有人踩）

| ❌ 做法 | 后果 |
|---|---|
| 把 key 写进代码 | 推到 GitHub 后，**几分钟内**被爬虫扫走，当天账单爆掉 |
| 把 `.env` 一起提交 | 同上。`.gitignore` 忘了写 `.env`，等于没写 |
| 把 key 写在 Streamlit 界面的输入框里 | 用户能看到、能复制、能拿去用你的钱 |

### ✅ 正确做法

**本地开发**：`.env` + `.gitignore`

```gitignore
.env
.venv/
__pycache__/
*.log
```

**Streamlit Cloud**：用 `st.secrets`

```toml
# .streamlit/secrets.toml （本地，不提交）
DEEPSEEK_API_KEY = "sk-xxx"
```

```python
# 代码里统一这样读
import os
try:
    import streamlit as st
    KEY = st.secrets["DEEPSEEK_API_KEY"]
except Exception:
    from dotenv import load_dotenv
    load_dotenv()
    KEY = os.getenv("DEEPSEEK_API_KEY")
```

**云服务器**：系统环境变量，或 systemd 的 `EnvironmentFile`

```bash
export DEEPSEEK_API_KEY=sk-xxx    # 写进 ~/.bashrc 或 systemd unit
```

### 一条铁律

> **密钥只存在于"运行环境"，不存在于"代码仓库"。**

检查方法（在项目目录执行）：

```bash
git log -p | findstr "sk-"     # Windows
git log -p | grep "sk-"        # Mac/Linux
```

**有输出 = 你已经泄露了**，立刻去平台吊销那个 key 重新生成。

## 四、什么时候需要 FastAPI（而不是 Streamlit）

Streamlit 有个硬限制：**它是给人点的，不是给程序调的。**

| 场景 | 用 Streamlit | 用 FastAPI |
|---|---|---|
| 你自己/同事在网页上问问题 | ✅ | 也可以 |
| 别的程序要调用你的能力 | ❌ | ✅ |
| 要做成微信机器人/小程序后端 | ❌ | ✅ |
| 要返回 JSON 给前端 | ❌ | ✅ |

### 最小 FastAPI（20 行）

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="我的 RAG 服务")


class AskRequest(BaseModel):
    question: str
    top_k: int = 3


class AskResponse(BaseModel):
    answer: str
    sources: list[str]


@app.get("/health")
def health():
    return {"status": "ok"}


@app.post("/ask", response_model=AskResponse)
def ask(req: AskRequest):
    if not req.question.strip():
        raise HTTPException(status_code=400, detail="问题不能为空")
    if len(req.question) > 500:
        raise HTTPException(status_code=400, detail="问题太长")

    answer, refs = do_rag(req.question, req.top_k)   # 你的 RAG 函数
    return AskResponse(answer=answer, sources=list(refs.values()))
```

**跑起来**：`uvicorn main:app --reload`，然后访问 `http://127.0.0.1:8000/docs`——**FastAPI 自动给你一个能点的接口文档页面**。

> 这个 `/docs` 页面是 FastAPI 最香的地方：**你不用写前端，就能测接口**。

### 什么时候**不需要** FastAPI

**你现在不需要。** 三个人用的小工具，Streamlit 足够。

加 FastAPI 的唯一理由是：**"有别的程序要调我"**。没有这个需求，加了只是多一层。

> 面试时被问"为什么用 Streamlit 不用 FastAPI"，答"因为我的用户是人不是程序，Streamlit 让我 2 小时做出界面"——这是加分回答。

## 五、上线后必须做的四件事

### ① 限流（防刷）

你的 key 挂在公网，就有人能刷。**哪怕是免费的额度，也会被刷光。**

```python
import time

_last_call = {}

def allow(user_id: str, interval: float = 2.0) -> bool:
    now = time.time()
    if now - _last_call.get(user_id, 0) < interval:
        return False
    _last_call[user_id] = now
    return True
```

**更简单的做法**：每次请求之间 `time.sleep(1)`，或在界面上禁用按钮直到返回。

### ② 输入长度限制

```python
if len(question) > 1000:
    st.warning("问题太长了，请精简到 1000 字以内。")
    st.stop()
```

**为什么**：一次 10 万字的问题，可能直接烧掉你几块钱。

### ③ 日志

```python
import logging

logging.basicConfig(
    filename="app.log",
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s",
    encoding="utf-8",
)
logging.info("Q=%s tokens=%s", question[:50], total_tokens)
```

**没有日志，出问题你只能靠猜。**

### ④ 错误兜底

```python
try:
    answer = do_rag(q)
except Exception as e:
    logging.exception("RAG 失败")
    st.error("服务暂时不可用，请稍后再试。")
    answer = None
```

**用户不需要看堆栈，你需要看日志。** 两者分开。

## 六、作品集：三个项目怎么包装

### 你手里有什么

| 项目 | 技术点 | 可量化成果 |
|---|---|---|
| P5 RAG v1 | 解析/切分/检索/生成/引用 | 10 题评测 |
| P6 RAG v2 | 混合检索/父块/评测体系 | 命中率 62%→81% |
| P7 Agent | Function Calling/工具设计/刹车 | 6 任务 + 3 破坏测试 |

**这三个是递进的**：从"能用"到"好用"到"会决策"。**这个递进关系本身就是故事。**

### README 的标准结构（每个项目都要有）

```markdown
# 项目名

一句话说明它解决什么问题（不要写"这是一个基于...的系统"，写人话）

## 演示
[截图 or 30 秒视频链接]

## 它解决了什么问题
- 痛点 1
- 痛点 2

## 技术方案
- 架构图（一张图）
- 关键决策：为什么选 A 不选 B

## 效果
- 指标：Recall@5 0.85，答对率 0.80
- 对比：优化前后表格

## 怎么跑起来
3 行命令

## 我踩过的坑
- 坑 1：... 怎么解决的
- 坑 2：...
```

### "我踩过的坑"这一节，是最值钱的一节

因为它证明**你真的做过**。招聘方看 10 份 README，9 份都在吹功能，只有 1 份在讲踩坑——**那份会被记住**。

例子：

> **坑：Chroma 默认会用自己的 embedding 模型**
> 我传了自定义向量但没传 `embeddings` 参数，导致库里存的是另一套坐标系的向量。查询不报错，但排序完全随机。排查了两小时才发现要用 `col.get(include=["embeddings"])` 看实际维度。

### 简历三句话（照这个模板写）

> **① 做了什么**：独立实现文档问答系统，支持 PDF 解析、语义检索与答案溯源。
> **② 怎么做的**：自建 20 题评测集，量化 Recall/Precision；通过父块扩展与 BM25 混合检索优化检索层。
> **③ 结果如何**：整体答对率从 60% 提升至 80%，精确信息类问题从 33% 提升至 100%。

**注意每一句都有"动词 + 方法 + 数字"。** 没有数字的简历句，等于没写。

### 面试会被问什么（提前准备）

| 问题 | 你要能答出 |
|---|---|
| "你的 RAG 怎么评估的？" | 20 题、四指标、怎么标 gold |
| "为什么用混合检索？" | 向量擅长语义、BM25 擅长精确词，RRF 融合因为量纲不同 |
| "Agent 怎么防死循环？" | 步数上限、重复签名检测、错误回传 |
| "密钥怎么管的？" | .env + .gitignore + 平台 secrets，从不在代码里 |
| "如果用户量涨 100 倍怎么办？" | 缓存、限流、向量库换 Milvus、异步、成本监控 |

> 最后那个问题没有标准答案，**它考的是你有没有想过**。

## 【常见误解】

**误解 1："部署就是把代码传上去。"**
不。部署要处理：依赖版本、密钥、端口、日志、限流、错误兜底。**传代码只占 20%。**

**误解 2："Streamlit 做的不是真产品。"**
对，它不是。但它能让你**在 2 小时内验证想法**。产品化是后面的事，别在验证阶段就追求产品级。

**误解 3："免费额度够用，不用管限流。"**
错。公网链接一旦被转发到群里，**十分钟就能刷光**。限流不是"以防万一"，是"必然需要"。

**误解 4："作品集要有 5 个项目才够。"**
错。**3 个做深 > 10 个做浅。** 面试官会挑一个往死里问，你答不出细节就完了。
