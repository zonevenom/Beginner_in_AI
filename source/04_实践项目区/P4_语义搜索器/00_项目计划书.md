## 1. 项目要做什么

### 一句话

给你自己的 20~50 条笔记/收藏/商品描述，做一个**按意思搜索**的小工具：输入"怎么把钱要回来"，它能找到"退款流程说明"。

### 验收标准

- [ ] 有 ≥20 条自己的真实文本
- [ ] 一次命令能建好索引，存成文件，重启不丢
- [ ] 查询返回 top-3 + 分数
- [ ] 有阈值：问库里没有的东西，会说"没找到"
- [ ] 能一键切换 top-k 和阈值（不改代码）
- [ ] 有一个网页界面（Streamlit）
- [ ] 有一张自己填的"5 个查询"评测表

### 明确不做

- ❌ 不做文档解析（PDF/Word）—— 那是 P5
- ❌ 不做生成回答，**只做检索** —— 这是关键区别
- ❌ 不做重排、混合检索 —— 那是 M5

> **这一版只做"找"，不做"答"。** 先把"找得准"这件事做扎实，M4 才有意义。

### ⚠️ 关于 embedding 服务（重要）

**DeepSeek 目前没有 embedding 接口**（以官网为准）。所以这一步你必须换一家。三个选择：

| 方案 | 需要做什么 | 成本 | 推荐度 |
|---|---|---|---|
| **智谱 BigModel** | 注册 → 拿 key → `embedding-3` | 有免费额度 | ⭐⭐⭐⭐ |
| **阿里百炼** | 注册 → 拿 key → `text-embedding-v*` | 有免费额度 | ⭐⭐⭐⭐ |
| **本地 `sentence-transformers`** | `pip install` + 下载 `bge-small-zh`（约 100MB） | 免费，但慢 | ⭐⭐⭐ |

**建议**：先用 API（最快跑通），M5 要反复实验时再考虑本地模型。

> 这也是一堂真实的工程课：**"聊天"和"向量"常常是两家公司。** 你的代码要能把它们分开配置。

### `.env` 里要两个 key

```
DEEPSEEK_API_KEY=sk-xxx          # 聊天用（M2 已有）
EMBED_API_KEY=xxx                # 向量用（新）
EMBED_BASE_URL=https://open.bigmodel.cn/api/paas/v4
EMBED_MODEL=embedding-3
```

> 把 `base_url` 和 `model` 也放进 `.env`，这样换厂商**不用改代码**。这是个小习惯，能救你很多时间。

### 为什么 `embed.py` 要单独一个文件

因为**"换 embedding 模型"是必然会发生的**（换厂商、升级模型、换成本地）。把它关在一个文件里，将来只改一处。

```python
# embed.py 的接口设计——只有两个函数，外部只认这两个
def embed_texts(texts: list[str]) -> list[list[float]]: ...
def embed_one(text: str) -> list[float]: ...
```

> **接口越窄，越好维护。** 这是软件工程最朴素也最有用的一条。

## 4. 项目流程图

```mermaid
flowchart TD
    subgraph 建索引
        A1[读 data/notes.json] --> A2[清洗文本<br/>去空行/去重]
        A2 --> A3[批量 embed<br/>每批 32 条]
        A3 --> A4[归一化]
        A4 --> A5[写入 vectors.json<br/>含 text + vec + model 名]
    end

    subgraph 查询
        B1[/输入查询/] --> B2[embed 查询<br/>同一模型！]
        B2 --> B3[归一化]
        B3 --> B4[矩阵乘法算全部分数]
        B4 --> B5[排序取 top-k]
        B5 --> B6{最高分 ≥ 阈值?}
        B6 -- 否 --> B7[返回"没找到"]
        B6 -- 是 --> B8[返回结果 + 分数]
    end

    A5 -.-> B4
```

### 三个必须看懂的连线

1. **建索引和查询必须用同一个模型**（图里我特意标了"同一模型！"）。混用 = 分数无意义。
2. **归一化在两边都要做**，这样才能用矩阵乘法。
3. **阈值判断在排序之后**，判断的是"最高分"，不是"每条都判断"。

## 5. 分步实现

### Step 1 · 准备你的数据（20 分钟）

`data/notes.json`：

```json
[
  {"id": "n1", "text": "退款需要 3-5 个工作日原路退回，运费由买家承担"},
  {"id": "n2", "text": "质量问题支持 7 天无理由退换，需提供开箱视频"},
  {"id": "n3", "text": "订单发货后可在【我的订单】里查看物流单号"},
  {"id": "n4", "text": "会员积分 100 分抵 1 元，单笔最多抵 20 元"},
  {"id": "n5", "text": "优惠券不可叠加使用，满 199 减 20"}
]
```

**数据要求（很重要）**：

| 要求 | 为什么 |
|---|---|
| 每条 **20~100 字** | 太短没语义，太长会稀释 |
| 至少 20 条 | 少于 20 条，测不出排序效果 |
| **包含 3~5 组"同一件事的不同说法"** | 不然你测不出语义检索的价值 |
| 包含 2~3 条"明显无关"的 | 用来测试阈值 |

> 偷懒的办法：直接用你的微信收藏、备忘录、知乎收藏导出。**用真实数据，你才会有真实感受。**

### Step 3 · 写 `embed.py`（25 分钟）

```python
import numpy as np
from openai import OpenAI

from config import BATCH_SIZE, EMBED_API_KEY, EMBED_BASE_URL, EMBED_MODEL

client = OpenAI(api_key=EMBED_API_KEY, base_url=EMBED_BASE_URL)


def embed_texts(texts: list[str]) -> list[list[float]]:
    """批量取向量。自动分批，避免一次传太多被拒。"""
    out = []
    for i in range(0, len(texts), BATCH_SIZE):
        batch = texts[i:i + BATCH_SIZE]
        resp = client.embeddings.create(model=EMBED_MODEL, input=batch)
        # 注意：返回顺序不一定等于输入顺序，要按 index 排
        items = sorted(resp.data, key=lambda d: d.index)
        out.extend([d.embedding for d in items])
    return out


def embed_one(text: str) -> list[float]:
    return embed_texts([text])[0]


def normalize(v):
    v = np.asarray(v, dtype=np.float32)
    return v / (np.linalg.norm(v) + 1e-10)
```

**`sorted(..., key=lambda d: d.index)` 这一行是重点。**

有些厂商返回的 `data` **不保证顺序**。你不排序，向量和文本就会错位——**而且不报错**，你会得到"搜 A 出来 B"的诡异结果。

> 这个坑我特意放在这里，因为它是"看不见的错误"，比报错可怕得多。

### Step 4 · 写 `index.py`（30 分钟）

```python
import json
import os

import numpy as np

from config import DATA_FILE, EMBED_MODEL, VECTOR_FILE
from embed import embed_texts, normalize


def load_notes(path=DATA_FILE):
    with open(path, encoding="utf-8") as f:
        raw = json.load(f)

    seen, notes = set(), []
    for n in raw:
        t = " ".join(n["text"].split())        # 压掉多余空白
        if not t or t in seen:
            continue
        seen.add(t)
        notes.append({"id": n.get("id", str(len(notes))), "text": t})
    return notes


def build(path=VECTOR_FILE):
    notes = load_notes()
    vecs = embed_texts([n["text"] for n in notes])

    data = {
        "model": EMBED_MODEL,                  # 记录模型名，防止混用
        "dim": len(vecs[0]),
        "items": [
            {"id": n["id"], "text": n["text"], "vec": normalize(v).tolist()}
            for n, v in zip(notes, vecs)
        ],
    }
    with open(path, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False)
    print(f"✅ 已索引 {len(data['items'])} 条，维度 {data['dim']}，模型 {data['model']}")
    return data


def load(path=VECTOR_FILE):
    if not os.path.exists(path):
        return build(path)
    with open(path, encoding="utf-8") as f:
        data = json.load(f)

    if data["model"] != EMBED_MODEL:
        print(f"⚠️ 索引是用 {data['model']} 建的，当前是 {EMBED_MODEL}，需要重建。")
        return build(path)

    matrix = np.array([it["vec"] for it in data["items"]], dtype=np.float32)
    return data, matrix
```

**记录 `model` 和 `dim` 这两个字段，是整个文件里最重要的设计。**

它让你（和未来的你）在换模型时**立刻收到警告**，而不是得到一堆莫名其妙的分数。

> 工程上这叫"**数据自描述**"。好的数据文件应该能自己说清楚"我是谁生成的"。

### Step 5 · 写 `search.py`（25 分钟）

```python
import numpy as np

from config import DEFAULT_THRESHOLD, DEFAULT_TOP_K
from embed import embed_one, normalize


def search(query: str, data, matrix, top_k=DEFAULT_TOP_K, threshold=DEFAULT_THRESHOLD):
    qv = normalize(embed_one(query))
    scores = matrix @ qv
    order = np.argsort(-scores)[:top_k]

    results = [
        {
            "score": float(scores[i]),
            "text": data["items"][i]["text"],
            "id": data["items"][i]["id"],
        }
        for i in order
    ]

    best = results[0]["score"] if results else 0.0
    if best < threshold:
        return [], best

    return [r for r in results if r["score"] >= threshold], best


def pprint(query, results, best):
    print(f"\n🔍 {query}")
    if not results:
        print(f"   没有相关内容（最高分 {best:.3f} < 阈值）")
        return
    for r in results:
        print(f"   {r['score']:.3f}  {r['text'][:60]}")
```

### Step 6 · 命令行入口（15 分钟）

```python
# main.py
import sys

from index import load
from search import pprint, search

if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "build":
        load(force=True)
        sys.exit(0)

    data, matrix = load()
    print("输入查询，回车搜索，输入 exit 退出。")
    while True:
        q = input("\n查询：").strip()
        if q.lower() == "exit":
            break
        if q:
            res, best = search(q, data, matrix)
            pprint(q, res, best)
```

**运行**：

```bash
python main.py build     # 建索引
python main.py           # 开始搜
```

### Step 7 · 加 Streamlit 界面（30 分钟）

```python
import streamlit as st

from index import load
from search import search

st.set_page_config(page_title="语义搜索器", page_icon="🔍")
st.title("🔍 语义搜索器")
st.caption("按意思找，不是按字找")

data, matrix = load()

with st.sidebar:
    st.header("参数")
    top_k = st.slider("返回条数", 1, 10, 3)
    th = st.slider("相似度阈值", 0.0, 1.0, 0.5, 0.01)

q = st.text_input("你想找什么？", placeholder="例如：怎么把钱要回来")

if q:
    res, best = search(q, data, matrix, top_k=top_k, threshold=th)
    if not res:
        st.warning(f"没有相关内容（最高分 {best:.3f}，低于阈值 {th:.2f}）")
    for r in res:
        with st.container(border=True):
            st.progress(min(max(r["score"], 0.0), 1.0), text=f"相似度 {r['score']:.3f}")
            st.write(r["text"])
```

**为什么把阈值做成滑块**：让你能**亲手感受**阈值对结果的影响。这比看十篇文章都管用。

## 6. 项目进化方向

| 等级 | 加什么 | 学什么 | 难度 |
|---|---|---|---|
| Lv.1 | 加"按分数过滤 + 高亮关键词" | 文本处理 | ⭐ |
| Lv.2 | 数据量到 1000 条，换 Chroma | 向量库 | ⭐⭐ |
| Lv.3 | 加元数据过滤（按类型/日期） | 结构化过滤 | ⭐⭐ |
| Lv.4 | 加关键词检索，做混合排序 | BM25 + 融合 | ⭐⭐⭐（M5） |
| Lv.5 | 检索完让模型"回答问题" | **RAG** | ⭐⭐⭐⭐（M4） |
| Lv.6 | 支持 PDF/Word 导入 | 文档解析 | ⭐⭐⭐（M4） |

> **Lv.2 的判断标准**：不是"数据多不多"，而是"你有没有觉得慢"。20 条数据上 Chroma 是浪费时间。
