## 1. 项目要做什么

### 一句话

做一个**能自己决定用哪个工具**的助手：会算数、会查时间、会换算单位、会在你的笔记里搜东西；并且**每一步你都能看到它干了什么**。

### 验收标准

- [ ] 4 个工具，都是"安全"的（没有 `eval`、没有删文件、没有外发）
- [ ] 用原生 Function Calling，**不用 LangChain**
- [ ] 有 3 道刹车：最大步数、重复调用检测、单次超时
- [ ] 每一步都有日志：第几步 / 调了什么 / 参数 / 结果 / 耗时
- [ ] 界面上能看到**完整的思考链**（哪一步调了什么）
- [ ] 问"做不到的事"时，它会**承认做不到**
- [ ] 没有运行框架（不装 LangChain / AutoGen / CrewAI）

### 明确不做

- ❌ 不做多 Agent 协作（一个就够）
- ❌ 不做联网搜索（要 API key，且引入不可控内容）
- ❌ 不做代码执行（危险）
- ❌ 不接真实业务系统

## 2. 工具与开发环境

> 🛑 **本项目零新增依赖。** 全用标准库 + 已装好的东西。

### 为什么坚持"不用框架"

| 用框架 | 不用框架 |
|---|---|
| 5 行跑起来 | 50 行跑起来 |
| 出问题不知道错在哪 | **每一行你都懂** |
| 面试问"原理"答不上 | 面试问"原理"你能画图 |

> **先用原生写一遍，再用框架。** 顺序反了，你会变成"只会调 API 的人"。
> 而且 Agent 框架版本变动极快，你学的 API 半年就废了，**原理不会废**。

### 为什么 `tools.py` 和 `schemas.py` 要分开

| 文件 | 给谁看 | 内容 |
|---|---|---|
| `tools.py` | **Python 解释器** | 真正的函数实现 |
| `schemas.py` | **模型** | 名字、描述、参数类型 |

**同一件事写两遍？** 是的，但这是必要的：

- 实现是给机器执行的
- schema 是给模型"阅读"的（描述写得好不好，直接决定它选不选对）

> 你可以用装饰器自动生成 schema，但对初学者来说，**手写一遍能让你体会"描述有多重要"**。

## 4. 项目流程图

```mermaid
flowchart TD
    A[/用户提问/] --> B[拼 messages<br/>system + user]
    B --> C[调 chat.completions<br/>带 tools]
    C --> D{有 tool_calls?}
    D -- 否 --> Z[输出最终答案]
    D -- 是 --> E{步数 ≥ max_steps?}
    E -- 是 --> Y[强制停止<br/>"我想太久了"]
    E -- 否 --> F{和上次调用完全一样?}
    F -- 是 --> X[强制停止<br/>"我卡住了"]
    F -- 否 --> G[逐个执行工具]
    G --> H{执行超时/报错?}
    H -- 是 --> I[把错误转成<br/>可读字符串]
    H -- 否 --> J[拿到结果]
    I --> K[追加 tool 消息]
    J --> K
    K --> L[写日志]
    L --> C
```

### 三条刹车分别在哪

| 刹车 | 位置 | 作用 |
|---|---|---|
| `max_steps` | D → E | 防死循环 |
| 重复检测 | E → F | 防"参数不变地重试" |
| 单次超时 | G → H | 防某个工具卡死 |

> **三个都要有。** 只有 `max_steps` 的话，它可能用 8 步做 8 次同样的错误调用——看起来"没超限"，实际全是浪费。

## 5. 分步实现

### Step 1 · 实现 4 个工具（50 分钟）

`tools.py`：

```python
import ast
import json
import operator
from datetime import datetime

# ---------- 工具 1：安全计算器 ----------
_OPS = {
    ast.Add: operator.add, ast.Sub: operator.sub,
    ast.Mult: operator.mul, ast.Div: operator.truediv,
    ast.Pow: operator.pow, ast.Mod: operator.mod,
    ast.USub: operator.neg, ast.UAdd: operator.pos,
    ast.FloorDiv: operator.floordiv,
}


def _eval(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval(node.left), _eval(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval(node.operand))
    raise ValueError("不支持的运算")


def calculate(expression: str) -> str:
    """只支持 + - * / // ** % 和数字。绝不用 eval。"""
    try:
        tree = ast.parse(expression.strip(), mode="eval")
        val = _eval(tree.body)
        if isinstance(val, float) and val.is_integer():
            val = int(val)
        return str(val)
    except ZeroDivisionError:
        return "错误：除数不能为 0"
    except Exception:
        return ("错误：无法计算这个表达式。只支持数字和 + - * / ** % 运算，"
                "例如 12*3+5。")


# ---------- 工具 2：当前时间 ----------
def get_current_time() -> str:
    now = datetime.now()
    week = "一二三四五六日"[now.weekday()]
    return now.strftime(f"%Y-%m-%d %H:%M:%S 星期{week}")


# ---------- 工具 3：单位换算 ----------
_UNITS = {
    "km": ("length", 1000.0), "m": ("length", 1.0), "cm": ("length", 0.01),
    "kg": ("weight", 1000.0), "g": ("weight", 1.0),
    "h": ("time", 3600.0), "min": ("time", 60.0), "s": ("time", 1.0),
}


def unit_convert(value: float, from_unit: str, to_unit: str) -> str:
    a, b = _UNITS.get(from_unit), _UNITS.get(to_unit)
    if not a or not b:
        return f"错误：不支持的单位。可用：{', '.join(_UNITS)}"
    if a[0] != b[0]:
        return f"错误：{from_unit} 和 {to_unit} 不是同一类单位，无法换算"
    return f"{value * a[1] / b[1]:g} {to_unit}"


# ---------- 工具 4：搜笔记 ----------
def search_notes(keyword: str, limit: int = 5) -> str:
    with open("data/notes.json", encoding="utf-8") as f:
        notes = json.load(f)

    hits = [n["text"] for n in notes if keyword in n["text"]][:limit]
    if not hits:
        return f"未找到包含「{keyword}」的笔记。建议换一个更短的关键词。"
    return "\n".join(f"- {h}" for h in hits)


TOOL_MAP = {
    "calculate": calculate,
    "get_current_time": get_current_time,
    "unit_convert": unit_convert,
    "search_notes": search_notes,
}
```

#### 四个实现细节，每个都有讲究

| 细节 | 为什么 |
|---|---|
| **不用 `eval`** | `eval` 是"执行任意代码"的后门。用 `ast` 白名单，从根上杜绝 |
| **错误返回字符串，不抛异常** | 抛异常会让循环崩；返回字符串能变成模型的"反馈" |
| **`is_integer()` 转 int** | 不然 `2.0` 会显示成 `2.0`，模型可能以为要保留小数 |
| **`搜索失败时给建议`** | "建议换更短的关键词"——这句会引导模型下一轮换个词重试 |

> 第 4 条是"工具设计"的精髓：**你要替模型想好"失败了该怎么办"，而不是只告诉它"失败了"。**

#### 三个"怎么写描述"的技巧

| 技巧 | 例子 |
|---|---|
| **写"什么时候用"** | "当用户问'现在几点'时使用" |
| **写"什么时候不用"** | "不要用它做单位换算（请用 unit_convert）" |
| **用 `enum` 收窄取值** | 单位只能是那 8 个，模型不可能填"公里"这种中文 |

> 第三点很重要：`enum` 让模型**没有机会填错**。你写"string"，它可能填"km"也可能填"千米"；你写 `enum`，它只能从列表里选。

### Step 3 · 写 Agent 循环（60 分钟，核心）

`agent.py`：

```python
import json
import time
from datetime import datetime

from openai import OpenAI

from config import CHAT_API_KEY, CHAT_BASE_URL, CHAT_MODEL, MAX_STEPS, LOG_PATH
from schemas import TOOLS
from tools import TOOL_MAP

client = OpenAI(api_key=CHAT_API_KEY, base_url=CHAT_BASE_URL)

SYSTEM = """你是一个会使用工具的助手。

规则：
1. 需要精确计算时，调用 calculate，不要自己心算。
2. 需要当前时间时，调用 get_current_time，不要猜日期。
3. 工具返回的是给你看的原始数据，请改写成自然语言回答用户，不要原样输出 JSON。
4. 如果没有合适的工具，直接告诉用户"我做不到这件事"，不要编造。
5. 每次只调用必要的工具。"""


def log(record: dict):
    record["ts"] = datetime.now().isoformat(timespec="seconds")
    with open(LOG_PATH, "a", encoding="utf-8") as f:
        f.write(json.dumps(record, ensure_ascii=False) + "\n")


def run_agent(question: str, max_steps: int = MAX_STEPS):
    messages = [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": question},
    ]
    trace = []
    last_sig = None

    for step in range(1, max_steps + 1):
        t0 = time.time()
        resp = client.chat.completions.create(
            model=CHAT_MODEL, messages=messages, tools=TOOLS, temperature=0,
        )
        msg = resp.choices[0].message
        latency = round(time.time() - t0, 2)

        # 没有工具调用 → 结束
        if not msg.tool_calls:
            trace.append({"step": step, "type": "final",
                          "content": msg.content, "latency": latency})
            log({"q": question, "step": step, "type": "final", "content": msg.content})
            return msg.content, trace

        # 关键：把"它要调用工具"这条消息也存进历史
        messages.append(msg)

        # 重复检测
        sig = json.dumps(
            [(c.function.name, c.function.arguments) for c in msg.tool_calls],
            ensure_ascii=False, sort_keys=True,
        )
        if sig == last_sig:
            stop = "我似乎卡住了（重复调用同样的工具），请换个问法。"
            trace.append({"step": step, "type": "stuck", "content": stop})
            return stop, trace
        last_sig = sig

        for call in msg.tool_calls:
            name = call.function.name
            raw_args = call.function.arguments or "{}"

            try:
                args = json.loads(raw_args)
            except json.JSONDecodeError:
                args = {}
                result = f"错误：参数不是合法 JSON（{raw_args}），请重新生成。"
            else:
                fn = TOOL_MAP.get(name)
                if fn is None:
                    result = f"错误：不存在名为 {name} 的工具。可用工具：{list(TOOL_MAP)}"
                else:
                    try:
                        result = str(fn(**args))
                    except TypeError as e:
                        result = f"错误：参数不正确（{e}）。请检查必填参数。"
                    except Exception as e:
                        result = f"错误：工具执行失败（{e}）。"

            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": result,
            })
            step_rec = {"step": step, "type": "tool", "name": name,
                        "args": args, "result": result, "latency": latency}
            trace.append(step_rec)
            log({"q": question, **step_rec})

    stop = f"我思考了 {max_steps} 步还没得出结论。要不要换个问法？"
    trace.append({"step": max_steps, "type": "max_steps", "content": stop})
    return stop, trace
```

#### 六个必须理解的点

| 点 | 为什么 |
|---|---|
| `messages.append(msg)` | **漏了它必崩**（API 报"tool 消息没有对应的 tool_calls"） |
| 先 JSON 解析再执行 | 参数可能是坏的 JSON，直接 `json.loads` 会抛异常中断整个循环 |
| `except TypeError` | 模型漏参数/多参数是常态，不是异常 |
| `result = str(fn(**args))` | 确保传给模型的是字符串 |
| 重复检测用"完整签名" | 只比名字不够——同名不同参数是合理的 |
| `trace` 同时返回 | 给你和界面用，**这是调试 Agent 的唯一手段** |

### Step 4 · 写界面（40 分钟）

`app.py`：

```python
import streamlit as st

from agent import run_agent

st.set_page_config(page_title="工具箱助手", page_icon="🧰")
st.title("🧰 工具箱助手")
st.caption("会算数、查时间、换单位、搜笔记")

if "history" not in st.session_state:
    st.session_state.history = []

q = st.chat_input("试试：现在几点？顺便算一下 365*24")

for item in st.session_state.history:
    with st.chat_message("user"):
        st.write(item["q"])
    with st.chat_message("assistant"):
        st.write(item["a"])
        with st.expander("🔍 看看它是怎么想的"):
            for t in item["trace"]:
                if t["type"] == "tool":
                    st.markdown(f"**第 {t['step']} 步** · 调用 `{t['name']}`")
                    st.code(f"参数：{t['args']}\n结果：{t['result']}",
                            language="text")
                elif t["type"] == "final":
                    st.markdown(f"**第 {t['step']} 步** · 输出最终答案")

if q:
    with st.chat_message("user"):
        st.write(q)
    with st.chat_message("assistant"):
        with st.spinner("思考中…"):
            answer, trace = run_agent(q)
        st.write(answer)
        with st.expander("🔍 看看它是怎么想的", expanded=True):
            for t in trace:
                if t["type"] == "tool":
                    st.markdown(f"**第 {t['step']} 步** · 调用 `{t['name']}`")
                    st.code(f"参数：{t['args']}\n结果：{t['result']}",
                            language="text")
                else:
                    st.markdown(f"**第 {t['step']} 步** · {t['type']}")

    st.session_state.history.append({"q": q, "a": answer, "trace": trace})
```

**"看看它是怎么想的"这个折叠面板，是这个项目最好的展示品。**

面试时打开它，让对方看到"第 1 步查时间，第 2 步算乘法"——**这比任何描述都有说服力**。

### Step 5 · 测 5 个任务（40 分钟）

| # | 任务 | 期望行为 | 实际 |
|---|---|---|---|
| 1 | "现在几点" | 调 1 次 `get_current_time` | |
| 2 | "1234 × 5678 等于多少" | 调 1 次 `calculate` | |
| 3 | "100 分钟是几小时" | 调 1 次 `unit_convert` | |
| 4 | "现在几点？顺便算 365×24" | **调 2 次**（时间 + 计算） | |
| 5 | "帮我订去上海的机票" | **不调工具，直接说做不到** | |
| 6 | "我笔记里有没有提到退款" | 调 `search_notes` | |

**重点看第 4 和第 5**：

- 第 4 题测"多工具串联"——它能不能在一次回答里调两个？
- 第 5 题测"边界感"——它会不会硬编一个航班号？

> 第 5 题如果它编了，说明 system 里那句"没有合适工具就说做不到"没生效。把这句话**移到 system 最前面**再试。

### Step 6 · 故意制造故障（30 分钟，最值钱）

**做三个破坏实验，验证刹车有效**：

| 实验 | 怎么造 | 期望 |
|---|---|---|
| 死循环 | 把 `search_notes` 改成永远返回"未找到" | 第 2 次相同调用被"重复检测"拦下 |
| 参数错 | 把 schema 里的 `expression` 改成 `expr`（实现不变） | 报"参数不正确"，且模型会尝试修正 |
| 工具崩 | 把 `unit_convert` 改成 `raise RuntimeError("炸了")` | Agent 不崩，说"工具执行失败"，然后可能换工具 |

> **能证明"我的刹车有效"的人，比"我的 Agent 能跑"的人少 10 倍。**
> 面试时讲这一段，直接拉开差距。

## 6. 项目进化方向

| 等级 | 加什么 | 学什么 | 难度 |
|---|---|---|---|
| Lv.1 | 加第 5 个工具：`search_docs`（复用 P5 的 RAG） | Agent + RAG 结合 | ⭐⭐ |
| Lv.2 | 加多轮对话（Agent 记住上文） | messages 管理 | ⭐⭐ |
| Lv.3 | 加"人工确认"：危险工具执行前弹窗 | 人机协同 | ⭐⭐⭐ |
| Lv.4 | 加并行工具调用（一次调多个） | 并发 | ⭐⭐⭐ |
| Lv.5 | 加"计划-执行"两阶段（先列计划再执行） | Plan-and-Execute | ⭐⭐⭐⭐ |
| Lv.6 | 加子 Agent（一个负责检索，一个负责计算） | 多 Agent | ⭐⭐⭐⭐⭐ |

### Lv.1 是最值的进化

**Agent + RAG = 真正有用的助手**：

```
用户：我们公司的退款政策是怎么规定的？
Agent：调 search_docs("退款政策") → 拿到 RAG 结果 → 总结回答
```

这比"纯 RAG"强在：它能**判断"这个问题该查文档还是该算数"**。
