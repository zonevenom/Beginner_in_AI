一、时间怎么分（先看这个，比课表重要）

时段时长干什么不要干什么
周六上午2 小时读理论讲稿 + 做练习不要开新项目
周日上午2 小时写项目代码（按计划书一步一停）不要重读理论
平日（任选 3 天）每次 15–20 分钟① 把周末代码再跑一遍 ② 改一个参数看变化 ③ 在我的讲稿里划一句重点不要学新内容
每周日晚上10 分钟填 02_学习进度看板.md + 错题本加一条不要"下周一定补上"

一周真实投入 ≈ 5 小时。16 周 ≈ 80 小时。这个量足够你从"会一点 Python"走到"能交付 RAG 应用"，前提是不断档。

断档是最大的敌人。缺一周不可怕，缺三周就回不去了。应对办法见第五节。

三、每周的固定动作（抄下来贴墙上）

周六 2h

  1. （10 min）打开进度看板，看上周错题
  2. （50 min）读讲稿，只读一遍，不懂的地方画问号，别停
  3. （30 min）做练习，先不看解析
  4. （20 min）对解析，把错的题抄进错题本
  5. （10 min）用一句话总结"这周我学会了什么"

周日 2h

  1. （10 min）打开项目计划书，看今天的任务清单
  2. （80 min）照着敲，每敲 10 行运行一次
  3. （20 min）故意改坏一个地方，看报错长什么样（这一步最值钱）
  4. （10 min）commit 一次代码

平日 3×15 min：只做"回锅肉"——重跑代码、改参数、背 3 个术语。

四、考核标准（怎么算"这个模块过了"）

每个模块必须同时满足三条，才允许进入下一个模块：

门槛具体标准
理论能不看讲稿，用自己的话把核心概念讲给一个外行听（3 分钟）
练习≥5 题里至少 4 题独立做对；做错的题能说出"我当时错在哪一步"
项目代码能跑通；能说出每一行关键代码为什么这么写；故意改坏能自己修回来

只满足"代码能跑"不算过。能改、能修、能解释才算过。

五、断档了怎么办（弹性规则）

情况处理
某周只完成一半不补课，直接把剩余部分并入下周，砍掉"进阶"部分，保住主线
连续两周没动不要从头再来。先花 30 分钟把上次的代码跑一遍，跑通即恢复
某个模块学不懂不要硬扛。跳到项目，先做出来再回头理解（做中学对初学者更有效）
想加速只加速 M1/M3，M4 和 M6 不能跳，它们是面试硬通货
想放弃打开 02_学习进度看板.md，看已经打了多少个勾

六、16 周后你手里有什么

  1. P5/P6 个人知识库问答系统（带评测、带出处）→ 简历第一行
  2. P7 多功能 Agent（会调工具、会重试）→ 简历第二行
  3. P8 部署好的网页链接 → 面试时直接打开给对方看
  4. 一个错题本和一个能讲清楚的脑子

面试官不缺会调 API 的人。缺的是能说"我的 RAG 召回率从 62% 提到 81%，因为改了三处"的人。M5 就是为这句话准备的。
